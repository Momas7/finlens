# F0 Fundação — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Monorepo funcional onde um usuário cria conta, faz login pelo web, recebe um workspace pessoal e acessa `/v1/me`, com Postgres protegido por RLS e CI verde.

**Architecture:** Monorepo pnpm + Turborepo. `apps/api` (Fastify) expõe Better Auth em `/api/auth/*` e rotas de negócio em `/v1/*`. `apps/web` (Next.js) faz proxy (rewrites) dessas rotas para a API, assim cookies ficam same-origin. `packages/db` contém schema Drizzle, migrations e políticas RLS; a API conecta com um role sem `BYPASSRLS` e define o contexto do tenant por transação.

**Tech Stack:** Node 24, pnpm (via corepack), Turborepo, TypeScript (strict), Biome, Vitest, Playwright, Fastify 5, Zod 4, Better Auth, Drizzle ORM + drizzle-kit, PostgreSQL 17, Next.js (App Router), Tailwind v4, shadcn/ui, Podman/Docker Compose, GitHub Actions.

**Spec:** `docs/architecture.md`

## Global Constraints

- Licença MIT. Repositório público: nenhum dado financeiro real, `.env` ou `fixtures/private/` versionado.
- Node 24 (`.nvmrc` = `24`), pnpm via corepack, `"type": "module"` em todos os pacotes.
- TypeScript `strict: true`, `noUncheckedIndexedAccess: true`.
- Lint/format com Biome na raiz (um único `biome.json`).
- Dependências instaladas com `@latest` estável no momento da instalação; versões ficam travadas no `pnpm-lock.yaml`.
- Portas: web `3000`, api `3333`, Postgres `5432`.
- Postgres 17 com `pg_trgm` habilitado.
- Dois roles de banco: `finlens_owner` (dono do schema, roda migrations) e `finlens_app` (`NOSUPERUSER NOBYPASSRLS`, só DML). A API e os testes de RLS usam sempre `finlens_app`.
- Tabelas de tenant têm `ENABLE` **e** `FORCE ROW LEVEL SECURITY`.
- IDs de workspace: `uuid`. IDs de usuário: `text` (padrão Better Auth).
- Senhas com argon2id (`@node-rs/argon2`), não o hash padrão do Better Auth.
- Cookies de sessão: `HttpOnly`, `SameSite=Lax`, `Secure` em produção.
- Logs (pino) nunca contêm `password`, `cookie`, `authorization` ou `set-cookie`.
- Toda variável de ambiente é validada com Zod na inicialização; ausência derruba o processo com mensagem listando as variáveis.
- Mensagens de commit: Conventional Commits, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

2. **Consulta sem contexto de tenant definido**: esperado zero linhas, nunca todas. — Task 3.
3. **Duas requisições simultâneas do mesmo usuário recém-criado**: esperado exatamente um workspace pessoal. — Task 4.
4. **Usuário cujo hook de criação de workspace falhou**: esperado que `/v1/me` crie o workspace sob demanda, não erro 500. — Task 4.

- policy `workspace_members`: `USING (user_id = app_user_id())`, `WITH CHECK` igual;
- `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO finlens_app`, `GRANT USAGE ON ALL SEQUENCES ...`, `ALTER DEFAULT PRIVILEGES FOR ROLE finlens_owner IN SCHEMA public GRANT ...` para tabelas futuras;

ADR 0002 documenta: por que RLS como defesa em profundidade, por que `FORCE`, por que dois roles, e o padrão de policy para tabelas futuras: `USING (workspace_id = app_workspace_id())`.
